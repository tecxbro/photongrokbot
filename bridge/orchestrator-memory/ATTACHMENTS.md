# Attachments and grouped option cards

Input is authorized and committed before bridge-controlled byte reads. A bounded worker preserves original attachment ID/name/MIME/size/duration and reports ready, unavailable or failed media against that original event, atomically adding an unacknowledged work revision. Later completion uses the existing wake path after the initial run or restart; it never waits for another user message. Consume continuationReason and inputRevision, and acknowledge only the consumed revision without replaying the original greeting. Paths come from the stored batch/media result; provider IDs never become raw filenames. HEIC conversion preserves the original and honest failure state. See [audio](AUDIO.md) for voice.

Outbound files must be ordinary private staged assets under the resolver's `data/outbound-assets`. The explicit `bun run enqueue -- --stage-file "$AUTHORIZED_EXPORT_PATH"` command can copy an authorized exported file from outside the instance; it does not grant send authority. Symlinks, directories, traversal, secret names and arbitrary instance paths are rejected. Validate every original member before conversion/submission; a missing middle asset cannot shift metadata.

An ordinary file uses a text payload with attachmentPath, optionally a caption. A visual choice uses all N cards for N >= 4 in one logical attachment_group, including five/seven. Maintain exact parallel attachmentPaths/cards arrays, batchId and stable action key. Card fields are optionId, title, url, caption, details, known price and priceQualifier; do not invent an amount.

Image Cards returns all files/metadata to Front Door. Front Door submits the canonical group or registers the strict cards-ready envelope. The runtime watchdog uses that same logical action identity, option-set revision, destination and source work revision. Claim recovery preserves this scope. Never scan filenames to infer successful delivery or create an independent send path. [Card delivery](../../skills/photon-image-card-delivery/SKILL.md) defines the complete command/envelope.

The runtime stores actual provider parent/part references without inventing IDs. Added reactions resolve from those records within the original conversation/line; any emoji returns exact known option details/price/URL. Ambiguity asks once. Unknown grouped send never becomes multiple retries or a split group.

Local queue acceptance does not prove the Photos-style stack appeared on a device. Use the [operating contract](../../docs/product-repair/OPERATING_CONTRACT.md) for state/authority and [privacy](../../docs/product-repair/PRIVACY.md) for retention.
