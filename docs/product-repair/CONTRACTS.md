# Product repair internal contracts (F0 / version 1)

`bridge/src/contracts.ts` freezes typed boundaries. Only coordinator edits contracts/types/runtime/package. Each lane may request a precise revision; never fork storage or protocol implementations.

## Private paths (lane 01)
`resolveInstancePaths(options?: { env?: Record<string,string|undefined>, instanceDir?: string, checkoutRoot?: string, testMode?: boolean }): InstancePaths` is pure (no mkdir/env/DB side effects). Fields: root, configPath (=instance.json), secretsDir, bridgeEnv, liveMiniEnv, dataDir, databasePath, inboundAttachmentsDir, outboundAssetsDir, viewsDir, modelsDir, toolsDir, liveMiniContextDir, backupsDir, logsDir. Default root `/workspace/photongrokbot-state`; override `PHOTON_INSTANCE_DIR`. Explicit test root and `PHOTON_TEST_MODE=1` mandatory for test entrypoints. `ensureInstancePaths(paths)` creates only validated private directories (0700), never initialises installation identity. `assertPrivateFile(path, allowedRoot)` canonicalises, rejects symlinks/traversal/non-files. `atomicPrivateWrite(path, content)` mode 0600. JavaScript Node-compatible module with coordinator-owned .d.mts declaration. Resolve paths without opening state on imports; legacy constants temporarily replaced during F1 wiring.

## Store (lane 02)
`openStore(options?: { paths?: InstancePaths; create?: boolean; testMode?: boolean }): BridgeStore` in storage.ts. Production default create=false; explicit setup/migration initialises identity. All wrappers call this store, no JSON mutable truth. Tests pass instance paths and create=true. `getStore()` is lazy. Short immediate synchronous transactions; foreign_keys, FULL, bounded busy, patched SQLite checked by query; WAL only on verified local supported filesystem. Schema and additional useful typed methods lane02-owned, requests shared additions through coordinator. `enqueue` prepares all children before single transaction. Claim checks happen in transaction again. `accept` atomically inserts event/pending + one installation-scoped onboarding reservation/action when requested. greetingOnly can suppress only the *first* bare greeting that code-owned onboarding answers; later greetings route. `formBatches` atomically makes per-space/line membership+wake. Media completion enriches existing event/batch, does not create independent task. Unknown handing off blocks duplicate task creation.

## Control CLI
All commands bounded, structured, stderr redacted. `bun run batch -- claim --batch-id ID`; `renew|complete --batch-id ID --run-id RUN --generation N`; `delegation-intent|delegation-receipt --json-stdin` use `{claim,task}` where task matches TaskBinding. Receipt is local record of native tool evidence, not a guessed native API. `read-batch -- ID` validates ID. `outbound-status -- --id ID` emits OutboundStatus only. `enqueue -- --json-stdin` accepts Submission and derives destination from stored batch/task, matches supplied payload.spaceId; rejects unknown/incompatible fields. Existing flags can be adapter ONLY when batch+run+generation+action/purpose also supplied. Node Live helper invokes Bun control commands and never imports sqlite or reads queue JSON. Operator staging command deliberately copies selected file to outbound-assets; no broad workspace allowlist.

## Integrated worker interfaces

`InboundController.receive(space,message)` validates the locked SDK event boundary and synchronously commits acceptance. Only afterwards may runtime cache an attachment reader, notify media, or attempt a receipt. `flushDue` keeps independent space/line deadlines; `flushAll` recovers persisted pending work on boot/shutdown. `createWakeDispatcher`, `createMediaWorker` and `createOutboundDispatcher` expose bounded `notify/drain/stop` lifecycles. Only runtime constructs Spectrum; delivery receives `resolveSpace({spaceId,lineId})` and verifies the returned binding.

The canonical presentation registry is `task-card-context` keyed by card ID with `{cardId,taskId,batchId,destination,viewUrl}` and an atomic `task-card-url` index keyed by the exact full private URL. `registerPresentation(claim,context)` checks the original task/batch/conversation, current claim and configured HTTPS host, then inserts an immutable pair. Authorized Live Mini setup records `live-mini-host/configured:{origin}`. The actual host URL is `/live-1` through `/live-10`, followed by the card ID and its capability query. Matching exact URL/context is mandatory; raw app sends cannot bypass the task-card ledger. Unrelated static/live app URLs retain their own validated supported path.

`enqueue(...,{presentation})` binds the presentation claim to every outbox child in the same operation transaction. Registration and publisher claim are local/remote distinct phases; the Node helper must recover their original identities through bounded Bun controls, never import `bun:sqlite` or poll old queue JSON. Publisher/progress conflicts cannot be resolved by changing request IDs or replaying old content at the newest revision.

`setup-state registry` returns only verified configured core-role IDs from private state, without secrets. `status` and `registry` are read-only snapshots. Normal wakes read this registry; they do not create resources. The first runtime start requires six-role/core setup and Moonshine completion evidence; later recorded media failure leaves text ready. Runtime uses the inherited kernel lock before opening one connection, recovers in-flight state once, stops scheduling before cleanup, and retains uncertain delivery evidence.
