# Sharing boundaries

A shared bot profile is not a copy of its account's VM. This product also needs bridge source, six configured roles, the Front Door routine, verified Moonshine installation and private durable state. Authorized setup reconstructs or reuses those resources; an ordinary wake never recreates them.

Ship source, redacted role/routine templates, tests, pinned dependency manifests and public provider references. Keep installation identity, DB/WAL, credentials, authorized sender, hosted line, provider sessions, view capability URLs, attachments, transcripts, task contexts, logs and backups outside the checkout. Model binaries and installed environments also stay outside the share.

Do not copy another account's worker roster, personal histories or bot IDs into active templates. Use the actual verified private registry. This policy does not delete existing bots or histories. Optional templates are inert until explicitly configured.

Core setup includes all six roles and mandatory Moonshine. Only after readiness does Front Door invite the first text to the bot's hosted line. Atomic onboarding reserves one greeting with confetti; first real work is retained. Live Mini enablement requires explicit authorization, independently of connector access.

Exports contain private content and require private handling. The export command omits credentials but is not a public share artifact. Repository ignore rules are not evidence that previously tracked content never escaped. Follow [privacy](docs/product-repair/PRIVACY.md), [secret handling](02-SECRETS.md), and [migration](docs/product-repair/MIGRATION.md).
